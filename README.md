# 무사히 — 현장 위험성평가 AI (작업 전 위험성평가)

2026 공공 AI 대전환 챌린지 세션1 · AI 정부 실험실 챔피언십(자유주제) 출품작

공공시설 현장 담당자가 "이동식 일자 사다리로 높이 4m 등기구 교체, 혼자 작업, 바닥 왁스 청소 직후"처럼 오늘 할 작업을 적으면(현장 사진은 선택), 기관의 위험요인 목록과 안전보건관리규정, 최근 아차사고를 근거로 **위험요인·가능성·중대성·위험성·감소대책·개선 후 위험성**을 정리한 위험성평가표를 만들고, 작업 전에 끝내야 할 조치가 남아 있으면 "작업 전 조치 필요"로 막아 주며, 작업 전 안전점검회의(TBM) 낭독 문안과 서명 기록지를 바로 만들어 주는 도구입니다. 아차사고를 등록하면 같은 작업의 기존 평가에 '수시평가 필요'를 표시합니다.

## 왜 필요한가

- 위험성평가는 사업주의 법적 의무(산업안전보건법)이지만, 시설관리 현장에는 전문 안전 인력이 부족하고 평가표가 해마다 같은 내용으로 복사되기 쉽습니다. 그날의 조건(높이, 혼자 작업, 젖은 바닥, 폭염)이 평가에 반영되지 않습니다.
- 아차사고를 기록해도 다음 평가에 이어지지 않아, 같은 사고가 되풀이됩니다.
- 작업 전 안전점검회의(TBM)는 해야 하는데 무엇을 말할지 매번 준비하기 어렵습니다.

## 접속 주소

- **공개 시연판(설치 없이 바로 보기)**: https://safety-risk.onrender.com  
  모의자료 전용이며, 무료 서버라 한동안 접속이 없으면 처음 열 때 30초~1분 걸릴 수 있습니다.

실행하면 브라우저가 자동으로 열립니다. 열리지 않으면 **http://localhost:8105** 로 접속하세요.

## 실행 방법

- **Windows 바로 실행판(설치 불필요)**: `safety-risk_윈도우_바로실행.zip`을 풀고 `run.bat`을 더블클릭하면 Python 설치·인터넷 없이 바로 시작합니다(Python 3.11과 라이브러리가 `runtime\` 폴더에 들어 있음). 저장소에는 `runtime\`을 넣지 않습니다.

필요한 것: Python 3.10 이상, 인터넷(처음 한 번 라이브러리 설치). 모델은 없어도 됩니다.

- **Windows**: `run.bat` 더블클릭
- **macOS·Linux**: `./run.sh`
- **직접 실행**: `pip install -r requirements.txt` 후 `python run.py`
- 종료: 실행 창에서 `Ctrl+C`

## 주요 기능

- **작업 설명 → 위험성평가**: 위험요인 목록의 '찾는 낱말'로 위험요인을 찾고, 찾은 근거 문구를 표시합니다.
- **그날의 조건 반영**: 설명에서 높이(m), 1인 작업, 체감온도, 운영 중(이용객 있음), 실외 여부를 읽어 가능성·중대성을 조정하고 이유를 하나하나 적습니다(예: "작업 높이 4m(기준 2m 이상) → 중대성 3", "미끄러운 바닥 위 사다리 작업 → 가능성 +1").
- **아차사고가 평가를 바꿈**: 같은 시설·같은 작업의 최근 아차사고가 있으면 가능성을 1 올리고 그 기록(파일·행)을 근거로 붙입니다. 새 아차사고를 등록하면 해당 작업의 기존 평가에 '수시평가 필요'를 표시합니다(규정의 수시평가 조문 근거).
- **판단 기준을 규정에서 읽기**: "위험성 6 이상이면 작업 전 감소대책 완료", "3 이상이면 작업 중 관리", 폭염 33℃·35℃, 높이 2m 같은 기준값을 기관 안전보건관리규정 조문에서 읽어 씁니다. 규정을 고쳐 올리면 기준이 바뀝니다.
- **작업 시작 판정**: 작업 전에 끝내야 할 감소대책이 남아 있으면 "작업 전 조치 필요", 모두 완료하면 "작업 시작 가능"으로 표시합니다. 감소대책마다 담당·기한·완료를 기록합니다.
- **작업 전 허가·빠진 조건 질문**: 밀폐공간·화기 작업이면 작업허가서를 안내하고, 사다리 작업인데 높이가 없거나 실외 작업인데 체감온도가 없으면 물어봅니다.
- **현장 사진(모델 연결 시)**: 사진을 넣으면 모델이 위험요인 목록의 코드로만 답하게 하고, 목록에 없는 코드는 버립니다. 사진에서만 나온 위험은 '현장 확인 필요'로 두고 담당자가 확인해야 평가표에 들어갑니다. 모델이 없으면 사진은 평가표에 첨부만 합니다.
- **문서**: 위험성평가표(판단 이유·허가·수시평가 사유·참여자 서명란 포함), TBM 기록지(낭독 문안·참석자 서명란)를 한글(HWPX)·워드·마크다운으로 만듭니다.
- **정기 평가 현황**: 규정의 "정기평가(매년 1회)" 조문을 읽어, 정기 평가 대상 작업마다 올해 평가했는지·수시평가가 필요한지·작업 전 조치가 남았는지를 보여 주고 '평가하기'로 바로 평가를 시작합니다.
- **현장이 가르치는 낱말**: 목록의 낱말로 못 찾은 위험을 '빠진 위험요인 추가'로 넣으면서 작업 설명 속 말(예: "트러스")을 적으면, 그 말을 위험요인의 '찾는 낱말'에 보태 다음 평가부터 자동으로 찾습니다. 작업 설명에 실제로 있는 말만 받고, 보탠 낱말은 '기준·자료'에서 따로 보이며 뺄 수 있습니다(원본 엑셀은 그대로). 높이 2m 이상 작업인데 떨어짐을 찾지 못하면 먼저 묻습니다.
- **기상청 날씨로 작업 시작 판정(공공데이터)**: "기상청 날씨"를 누르면 기상청 단기예보의 기온·습도로 체감온도를 계산(기상청 여름철 체감온도 식)해 채우고, 발표 중인 기상특보를 가져옵니다. 실외 높은 곳 작업인데 강풍·호우·대설·태풍 특보 중이면 "작업 전 조치 필요"로 막습니다(산업안전보건기준에 관한 규칙, 악천후·강풍 시 작업 중지). 실내 작업은 막지 않습니다.
- **긴급재난문자로 수시평가(공공데이터)**: 현황의 "재난문자 확인"으로 우리 지역에 온 재난문자를 받아, 폭염·강풍·호우 같은 종류와 겹치는 위험요인이 있는 평가(실외 재난은 실외 작업만)에 '수시평가 필요'를 표시하고 TBM 문안에 넣습니다.
- 두 기능 모두 키(`DATA_GO_KR_KEY`, `SAFETYDATA_KEY`)가 없으면 예시 자료로 동작하고 화면에 "예시 자료"라고 표시합니다. 키는 `keys.example.bat`을 `keys.bat`으로 바꿔 넣거나 환경변수로 넣습니다.
- **엑셀**: 위험성평가표(판단 이유 포함)와 위험성평가 대장(모든 평가의 위험요인·판정 + 정기 평가 대상 작업 현황)을 xlsx로 받습니다.
- **현황**: 작업 전 끝내야 할 미완료 조치, 기한 지난 조치, 수시평가 필요 평가를 한눈에 봅니다.
- **오늘 작업 브리핑(외부 자료 종합 해석)**: 현황 맨 위에서 평가마다 기상청 체감온도·기상특보, 긴급재난문자, 같은 작업의 아차사고, 끝나지 않은 작업 전 조치를 엮어 '작업 중지·시작 전 조치·주의하며 진행·시작 가능'으로 규칙 판정하고, AI가 그 판정만으로 우선순위와 챙길 점을 씁니다.
- **물어보기(이어 묻기)**: "사다리 작업 안전 기준은?" 다음에 "그럼 2m 넘으면?"처럼 이어 물으면 앞 질문의 위험요인을 이어받아 기관 규정 조문·위험요인 목록·아차사고·평가 현황에서 답하고, 답에 쓴 사실과 근거 칩을 보여 줍니다.
- **평가표 미리보기·고쳐서 내려받기**: 화면을 반으로 나눠 왼쪽에서 평가표 초안을 블록별로 고치면 오른쪽 미리보기가 바로 바뀝니다. "위험요인마다 AI 해설 넣기", "AI로 종합 의견 쓰기", 문단별 "AI 다듬기", 현장 사진 넣기(평가 때 넣은 사진은 자동 포함) 후 한글·워드로 내려받습니다. TBM 창의 "AI로 말하기 쉽게 다시 쓰기"는 낭독 문안을 현장 말투로 바꿉니다.

## 작동 방법 (시연 순서)

1. **새 위험성평가**에서 "예시 채우기" → "위험성평가 만들기". 떨어짐(위험성 9)·감전(9)·넘어짐(6)·맞음(4)과 각 판단 이유, "작업 전 조치 필요" 판정이 나옵니다.
2. 떨어짐의 '최근 아차사고' 칩을 눌러 근거 행을 확인합니다.
3. 위험성 6 이상 항목의 감소대책을 체크하면 판정이 "작업 시작 가능"으로 바뀝니다.
4. "작업 전 회의(TBM)"로 낭독 문안을 보고 서명 기록지를 한글로 내려받습니다. 위험성평가표도 내려받습니다.
5. **새 위험성평가**에서 정기 평가 대상 작업 중 '수영장 염소 약품 투입'을 고르고 설명을 적어 평가합니다.
6. **아차사고**에서 "예시 채우기" → "등록"하면 방금 평가한 작업에 '수시평가 필요'가 표시됩니다.
7. **기준·자료**에서 판단 기준(규정 조문)과 위험성 행렬, 위험요인 목록을 확인합니다.

발표·영상용 대본은 [시연대본.md](시연대본.md)에 있습니다.

## 모델(LLM) 연결과 교체

- 모델 없이도 모든 기능이 규칙으로 동작합니다. 모델은 ① 낱말로 못 찾은 위험요인 제안 ② 현장 사진 판독 ③ 문장 쓰기(물어보기 답, 위험요인 해설, 종합 의견, TBM 문안, 오늘 작업 브리핑, 문단 다듬기)에 씁니다. 가능성·중대성 조정과 판정은 모델이 하지 않습니다.
- 모델이 쓴 문장에 근거 사실에 없는 숫자나 위험요인 코드(H01 등)가 하나라도 있으면 버리고 규칙 문장을 쓰며, 이유를 화면에 표시합니다. 모델 호출은 1분에 40번으로 묶습니다.
- **업스테이지 솔라(Solar) 연결 예**: `LLM_PROVIDER=openai`, `LLM_BASE_URL=https://api.upstage.ai/v1`, `LLM_MODEL=solar-pro4`, 키는 `LLM_API_KEY` 환경변수. 공개 시연판(render.yaml)도 이 값으로 연결합니다. 이 개발 환경에서는 업스테이지 서버에 접속할 수 없어 같은 형식의 가짜 모델 서버로 시험했습니다.
- 모델 제안은 대조를 거칩니다. 글 제안은 목록에 있는 코드이고 근거 문구가 작업 설명에 그대로 있어야 받고, 사진 제안은 목록에 있는 코드만 받아 '현장 확인 필요'로 둡니다.
- 화면 오른쪽 위 **모델 배지**나 `config.json`(예시: `config.example.json`)에서 바꿉니다. OpenAI 호환 API(행정안전부 AI 공통기반, vLLM, Ollama `/v1` 등)와 Ollama 기본 API를 지원합니다. 사진 판독은 사진을 받는 모델(예: Gemma 3 계열)에서만 동작하고, 받지 못하는 모델이면 사진은 첨부만 됩니다.
- 모델 검증: `모델검증.bat` 또는 `python tools/verify_models.py --base-url <주소> --models <모델1> <모델2>` → `verify_report.md`(사진을 받지 못하는 모델은 '지원 안 함'으로 표시). 모델 없이 연결 경로만 시험하려면 `--mock`.

## 원본 보호와 데이터 위치

- 기관 자료는 작업 폴더(`data/kb`)에 사본으로 두고 읽기만 합니다. 평가·아차사고·사진·작업 기록은 `data/`에만 저장합니다(설정 `data_dir` 또는 환경변수 `APP_DATA_DIR`).
- 화면은 이 PC에서만 열리며(127.0.0.1), 다른 웹사이트에서 보낸 요청은 거부합니다.

## 점검

- `python tests/smoke_test.py`: 평가·조건 반영·판정·문서·아차사고 수시평가·사진·보안 경로, 기상청 날씨·재난문자(예시 자료), 오늘 작업 브리핑, 물어보기, 평가표 고쳐서 내려받기(사진 포함)를 차례로 호출하고, 가짜 OpenAI 호환 모델 서버로 AI 답변·이어 묻기·지어낸 숫자·코드 차단·해설·종합 의견·TBM 문안·브리핑까지 시험합니다(50개 항목).
- `python tools/verify_models.py --mock`: 가짜 모델 서버 두 종류로 글·사진 요청 경로를 시험합니다. 하나는 근거 없는 제안을 일부러 섞으며, 앱이 걸러 내는지 확인합니다.

## 알려진 제약

- 위험요인은 목록의 낱말로 찾으므로 목록에 없는 표현은 놓칠 수 있습니다. 빠진 위험은 '위험요인 추가'로 넣고, 목록 엑셀에 낱말을 보태면 다음부터 찾습니다.
- 가능성·중대성 3단계와 조정 규칙(1인 작업 +1, 아차사고 +1 등)은 출발점이며, 담당자가 현장에서 확인해 고친 값이 평가표에 들어갑니다(고친 내역은 이유에 기록).
- 개선 후 위험성은 '감소대책을 모두 하면 가능성이 1로 내려간다'는 가정으로 계산합니다.
- 관련 기준은 법령 이름과 주제까지만 적었습니다. 세부 조문은 국가법령정보센터에서 확인해야 합니다.
- 사진 판독은 가짜 모델 서버로 연결 경로만 시험했고, 실제 비전 모델의 정확도는 시험하지 못했습니다. 시연용 사진은 그림입니다.
- 공공데이터 연동은 개발 환경에서 기상청·재난안전데이터공유플랫폼에 접속할 수 없어 응답 모양을 흉내 낸 자료로만 시험했습니다.
- 로그인·권한 관리는 없습니다. 모의자료의 기관·시설·인물·사건은 모두 지어낸 것입니다.

## 정확도 성적표와 서비스 구조

- `python tools/eval.py`를 실행하면 `검증결과/정확도_성적표.md`와 `scorecard.json`이 만들어집니다. 모델·인터넷 없이 누구나 같은 결과가 나오며(무작위 자료는 시드 고정), 틀린 문항은 고치지 않고 그대로 적고, 무엇을 고친 뒤 쟀는지 측정 이력을 남깁니다(`--note "..."`).
- 문항은 개발자가 적은 것이라 블라인드 시험이 아닙니다. 그래서 문항을 '앱을 고칠 때 쓴 묶음'과 '고칠 때 보지 않고 한 번만 잰 묶음'으로 나눠 따로 보여 줍니다.
- 화면의 **서비스 구조·검증** 탭에서 처리 단계, 틀린 답을 막는 장치, 성적표, 모델 교체 실측 결과를 볼 수 있습니다.
- **모델 교체 실측**: `모델검증.bat`(또는 `python tools/verify_models.py --models 모델1 모델2`)을 실제 모델로 돌리면 `검증결과/model_check.json`이 생기고 화면 머리에 모델별 통과 수가 표시됩니다. 가짜 모델 시험(`--mock`)은 `model_check_mock.json`에 따로 남기며 실측으로 표시하지 않습니다.
- 접근성: 화면 맨 위 '본문 바로가기', 글자 크기 3단계(가·가+·가++, 브라우저에 기억).
- 개인정보 가림: 작업 설명·아차사고 글에 적은 주민번호·전화·계좌·카드·이메일·여권 번호를 저장·모델 전달 전에 ○○○로 가립니다.

## 공개 시연판 올리기(선택)

- 저장소에 `render.yaml`이 들어 있어 Render(render.com)에 저장소를 연결하면 그대로 올라갑니다. 다른 곳에 올릴 때는 환경변수 `APP_HOST=0.0.0.0`, `PORT`(호스팅이 정함), `PUBLIC_DEMO=1`을 주고 `python run.py --no-browser`로 실행합니다.
- `PUBLIC_DEMO=1`이면 모델 설정 바꾸기를 막고(업무바통은 서버 폴더 읽기·문서시스템 연결도 막음), 한 번에 올리는 크기를 40MB로 제한하며, 화면 위에 '모의자료로만 써 보세요' 안내를 띄웁니다.
- 공개 시연판에는 실제 업무자료·개인정보를 넣지 마세요. 무료 요금제는 디스크가 임시라 넣은 자료가 재시작 때 지워집니다.
